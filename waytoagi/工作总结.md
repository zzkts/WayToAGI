## 2. 产品定位与核心循环

单模式、无止境的物理弹珠游戏。没有选关、没有固定回合数。

```text
一次拉杆，弹簧连续回弹，整组 3 颗白球出膛
  ↓
左右倾斜手机，Physics2D.gravity 横向分量连续变化
  ↓
落洞：弹珠倍率 × 洞口倍率 × 基础积分 × 同洞连击
  ↓
本循环齐射次数用完，判定门槛
  ↓
自动弹出兑换：附魔 / 引爆 / 减少挡板
  ↓
达标进入下一循环；未达标同一循环重试（累计得分与解锁保留）
  ↓
累计 1,000,000 → 通关面板 → 无尽模式
```

### 不可回退的设计约束

1. **一拉全发**：一次拉杆发射整组弹珠，不改回逐颗手动发射。
2. **单向上边框凹陷**：上边框是连续 `EdgeCollider2D` 半圆凹槽，不是弯曲钉阵；直径固定 `6.17`，不能跨过发射道。
3. **单向闸门 + 全高隔板 + 弹簧下 V 形挡板**：三层保障，台面球不能进入发射道。
4. **8 个洞全部在隔板左侧**：不改回把洞放到弹簧下方。
5. **不做多关卡 / 选关系统**：用户明确否决过。
6. **标准弹珠无限**：不重新引入弹珠购买、库存、付费弹珠。
7. **兑换只扣可用积分**：累计得分只增不减。
8. **5.2 三洞表是废案**：保留原有 8 洞（4 奖励 + 4 空穴），不实现 ×1/1000、×3/5000、×5/20000 三洞表。

## 3. 本轮 V3 改动

### 3.1 配置与存档

- `GameConfig` 重写为 V3 结构：`economy`、`loop`、`explosion`、`baffle`、`balls`、`enchants`、`holes`。
- 删除 `alwaysAvailable`、`unitPrice`、`upgradeBasePrice`、`upgradePointsPerLevel`、`maxUpgradeLevel` 等 V2 字段。
- `BallDef` 简化为标准白球；`EnchantDef` 新增两档附魔；`HoleDef` 只保留倍率、基础分、颜色、位置、空穴标记。
- `SaveData` 升级到 V5：新增 `loopIndex`、`goalReached`、`enchantTier`、`explosionUnlocked`、`baffleCount`、`bestLoopScore`；删除库存、解锁、洞等级、旧技能等级。
- `SaveSystem` 沿用旧 PlayerPrefs 键，`version < 5` 时保留累计得分与可用积分，重置循环与兑换进度。

### 3.2 计分与循环

- `ScoreManager` 只保留：弹珠倍率 × 洞口倍率 × 基础积分，再乘同洞连击。
- 同洞连击由 `ScoreRules.ComboMultiplierFor` 计算：×1/×2/×4/×8，封顶 ×8；换洞、空穴、漏球归零。
- 得分按 1:1 同时累加 `totalScore` 与 `credits`；兑换只扣 `credits`。
- 新增 `LoopManager`：随机齐射次数、三档阈值、百万目标、循环推进与重试。
- `GameManager` 状态改为 `Menu / Exchange / Aim / BallFlight / Resolving / Victory`；删除商店阶段、阶段过场、里程碑、护盾、全中、头奖、连锁、狂热。

### 3.3 附魔、引爆与挡板

- 附魔决定弹珠主体、描边、高光与彗星拖尾颜色；赤红 ×2、湛蓝 ×5。
- `MarbleController` 每累计 10 次碰撞触发一次引爆，半径 1.2 世界单位（120px），推力 8，只推动其他飞行中的弹珠。
- `Baffle` 为运动学挡板，按 2 秒周期往返，总行程 1.2（±0.6）。
- `BoardBuilder` 构建 3 块挡板，由存档 `baffleCount` 控制前 N 块显隐；初始 1 块。
- 兑换只保留：附魔、引爆、减少挡板。奖励洞升级与洞技能已删除。

### 3.4 UI

- 主 HUD：本次齐射 / 本循环得分 / 累计得分 / 可用积分、百万进度条、同洞连击徽章、当前附魔与引爆状态、循环信息。
- 循环结束自动弹出「循环结算与兑换」：显示达标 / 未达标、差额、三项永久兑换。
- 主菜单说明无限白球、动态循环、倾斜控球、同洞连击、兑换与百万目标。
- 新增通关面板；设置页更新为 V5 重置范围。
- 得分飘字使用新公式，不再显示头奖 / 连锁 / 狂热。

### 3.5 删除的旧文件

- `Assets/Scripts/Runtime/UI/HUDStage.cs`：旧阶段过场，调用已删除的 `ContinueStageTransition`。
- `Assets/Scripts/Runtime/Core/UpgradeCatalog.cs`：旧附魔 / 弹珠技能 / 洞技能目录。
- `Assets/Scripts/Runtime/Gameplay/RotatingBar.cs`：旧旋转挡板，已被 `Baffle` 取代。

### 3.6 音频系统

- 新增 `AudioManager` 单例：业务脚本只调用 `Play(id)` / `PlayBgm(id)`，不持有 `AudioSource`，不直接调用 `PlayOneShot`。
- 新增 `audio_config.json`：14 条音效 + 3 首 BGM，字段覆盖音量、pitch 范围、并发上限、最小间隔、优先级、循环与淡入淡出。主配置在 `StreamingAssets`，打包前同步到 `Resources/Config`。
- 17 个音频文件从 `Assets/Audio` 移动到 `Assets/Resources/Audio/SFX|Music`，以便 Unity 运行时通过 `Resources.Load` 可靠加载；文件名和交付标准一致，原目录保留交付说明与 README。
- 音效导入改为 `Decompress On Load` + `Preload Audio Data` + `Vorbis`；BGM 改为 `Streaming` + 不预加载。
- 已接线：落洞基础音 + 连击 1~5 级叠音、发射、撞钉、撞挡板、引爆、循环未达标、百万通关、按钮点击、兑换成功；BGM 在菜单 / 玩法 / 兑换之间交叉淡入淡出。
- 同一音效在最小间隔内重复触发直接丢弃；撞钉并发 4、撞挡板并发 2；对象池满时高优先级抢占低优先级。
- 设置页新增音乐 / 音效开关，状态写入 PlayerPrefs，重开游戏保留。
- 缺失文件只输出 `[AudioManager] 缺少音频文件：<文件名>` 并跳过，不中断游戏。
- 音量分 Master / BGM / SFX 三个逻辑组，由配置驱动；BGM 每条配置本身已比 SFX 低约 10 dB，组增益默认 0，避免重复压低。

4. **挡板初始 1 块**：配置最多 3 块，但当前只能减少不能增加；若要展示 3 块挡板的复杂度，需要调高 `economy.startingBaffleCount`。
5. **多球数量**：策划案把多球数量列为待决项；当前固定 3 颗，需真机确认引爆价值与画面密度。

8. **默认 0 初始积分**：首次兑换要等第一轮结束；若希望首轮就能兑换，可调 `startingCredits`。
9. **同洞连击跨齐射保留**：当前只在换洞 / 空穴 / 漏球 / 新循环时清零，未在每次齐射开始时清零；需确认这是否符合预期。
10. **百万目标节奏**：保留原有 8 洞的 50/120/260/300 基础分后，单球收益明显低于策划案 8.1 的 1,000~100,000 量级；达到 1,000,000 需要较长积累。建议真机记录每循环得分后，再决定整体放大洞口基础分还是下调目标。
11. **半圆凹槽与多分辨率**：V2 几何保留，仍需多分辨率与真机检查。
12. **Android 真机未验证**：加速度计轴向、校准、安全区、性能均未实测。
13. **Android 模块与 APK 未验证**：`C:\Program Files\Unity 6000.3.8f1` 是手动安装，当前只有 Android Build Support 主模块，`OpenJDK`、`SDK`、`NDK` 均缺失，构建报 `JDK not found`；需用管理员权限补装 **Android SDK & NDK Tools** 与 **OpenJDK**。构建入口已加入工具链前置检查，会直接列出缺失路径。
14. **Android 签名与架构**：当前按 ARM64 + 调试签名构建，可直接侧载测试；正式发布需要自定义 keystore，Google Play 需要 AAB，且旧 32 位设备无法安装当前 APK。
15. **Android 图标**：尚未配置应用图标，构建使用 Unity 默认图标。
16. **Android 输入警告**：`Active Input Handling = Both` 在 Android 上会有非致命警告；项目只用旧版 `Input`，发布前可改为 **Input Manager (Old)** 并重启 Unity。
17. **没有 `AudioMixer.mixer` 资产**：Master / BGM / SFX 三个逻辑组目前由 `AudioManager` 读取配置后直接换算到 `AudioSource.volume`，能实现分组音量与全局开关，但无法在 Unity 的 Mixer 面板里做 DSP、快照或给音频设计师调总线。若后续需要，再补 `.mixer` 并替换 `AudioManager` 的音量出口。
18. **BGM 组增益默认为 0**：每首 BGM 的 `volumeDb` 已是 −12 ~ −14 dB，若再把 `bgmGroupVolumeDb` 设为 −10 会重复衰减。需要整体压低 BGM 时只改这一个字段。
19. **音频包体**：17 个文件放在 `Resources` 下会整体打进包，当前约 7.7 MB。若后续音频增多或包体吃紧，应迁移到 Addressables 或按场景拆分加载。
20. **落洞叠音余量**：`score_base` 与 `combo_0x` 同时以 −2 dB 播放，若再叠加撞钉 / 引爆存在削波可能。试听时若听到破音，优先把 `sfxGroupVolumeDb` 调到 −3 ~ −6 dB，不要逐条改音量。

## 10. 关键决策备忘

- **5.2 三洞表是废案**：保留 V2 的 8 洞布局与 1/3/8/12 倍率、50/120/260/300 基础分。
- **多球保留 3 颗**：引爆需要多颗弹珠同场；策划案未给定数量，选 3 作为首版。
- **积分 1:1**：让 10,000 ~ 50,000 的兑换价格在合理循环数内可达到。
- **同洞连击跨齐射保留**：只在换洞 / 空穴 / 漏球 / 新循环时清零，强化「持续控同一个洞」的玩法。
- **挡板总行程 120px**：配置 `amplitude=1.2` 按总行程处理，单侧 ±60px，避免长挡板穿墙。
- **挡板初始 1 块**：遵循策划案「首版先放一个」的建议，兑换只能减少。
- **失败重试同一循环号**：累计得分、可用积分、附魔与兑换进度全部保留，只重置本循环尝试。
- **通关后失败不再拦截**：`MeetsThreshold` 在 `goalReached` 后恒为真，保证无尽模式不被门槛卡住。
- **不做多关卡**：保持单模式无止境。
- **音频配置驱动**：音效 ID、文件名、音量、pitch、并发、间隔、优先级、BGM 淡入淡出全部在 `audio_config.json`；增删音效只改配置与文件，不改业务代码。
- **音频放 Resources**：17 个文件总量约 7.7 MB，直接用 `Resources.Load` 最稳，避免 StreamingAssets 在 Android 上无法同步读取或需要 UnityWebRequest；代价是全部进包。
- **不建 `.mixer`**：Master / BGM / SFX 三个逻辑组在 `AudioManager` 内按 dB 换算实现，减少资产依赖；若需要 DSP 或可视化混音再补。
- **BGM 组增益 0**：BGM 单曲配置已压低约 10 dB，组增益只作为整体微调入口，默认不重复衰减。
- **撞钉 / 撞挡板音在引爆解锁前也播放**：碰撞反馈属于物理手感，不应与「引爆」技能解锁状态绑定。
