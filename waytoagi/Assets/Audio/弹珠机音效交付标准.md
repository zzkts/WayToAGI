# 弹珠机音效交付标准（Audio Delivery Spec）

> 用途：把音效文件与播放位置一次性交给编码 Agent（Cursor / Codex），让其按本文件完成全部音频配置。
> 项目：《弹珠机》Unity 2D 移动端 MVP
> 版本：v1.0

---

## 一、给 Agent 的执行指令

把本文件和全部音频文件一起提供，并附上这段话：

```
按《弹珠机音效交付标准》完成音频系统配置：
1. 音频文件放在 Assets/Audio/SFX/ 与 Assets/Audio/Music/ 下（见第二节）。
2. 新建 AudioManager 单例，按第五节的配置表统一播放，禁止在业务脚本里直接调用 AudioSource.PlayOneShot。
3. 严格按第三节的事件、音量、pitch 范围、并发上限配置。
4. 缺失的音频文件不要报错，按第七节处理，并在完成后列出缺失清单。
5. 先输出实现计划（文件清单 + 关键改动点），确认后再写代码。
6. 不要改动弹簧发射、计分、连击、商店的既有逻辑。
```

## 四、Unity 技术实现要求

1. **AudioMixer 分三组**：`Master` / `BGM` / `SFX`。BGM 组整体比 SFX 组低 10 dB，保证音效始终可辨。
2. **统一入口**：新建 `AudioManager` 单例，对外只暴露 `Play(string id)` 接口。业务脚本（MarbleController、RewardHole、ShopManager 等）不得持有 AudioSource 或直接调用 `PlayOneShot`。
3. **并发控制**：同一音效在「最小间隔」时间内重复触发时直接丢弃，不排队。撞钉音并发上限 4，超出时丢弃新的触发。
4. **随机 pitch**：按表中范围随机，避免同一音效反复播放产生机械感。
5. **2D 音效**：本项目为 2D 游戏，所有 AudioSource 的 `Spatial Blend` 设为 0（2D）。
6. **导入设置**：
   - 音效：`Load Type = Decompress On Load`、`Preload Audio Data = true`、`Compression Format = Vorbis`
   - BGM：`Load Type = Streaming`、`Preload Audio Data = false`
7. **优先级**：爆炸音 > 落洞与连击音 > 撞钉与撞挡板音 > UI 音。并发满时低优先级让位。
8. **全局开关**：提供 `SetSfxEnabled(bool)` 与 `SetBgmEnabled(bool)`，状态写入 PlayerPrefs。

## 六、验收标准

1. 清单中全部 17 个音频文件都已导入，每个触发事件都能播放对应音效，音色与事件语义匹配。
2. 连续落洞 10 次，不出现爆音、削波或音量骤变。
3. 弹珠在钉阵中连续碰撞时，撞钉音不卡顿、不叠加成噪音（并发上限生效）。
4. BGM 与音效同时播放时，音效始终清晰可辨，不需要调大音量。
5. 连击从 1 级升到 5 级，能明显听出音调逐级升高。
6. 关闭音效开关后游戏正常运行，重新打开后音效恢复。
7. 缺失的音频文件不会导致报错或游戏中断。
8. 修改配置文件即可调整音量、pitch 与并发，不需要改代码。

---

## 七、文件缺失处理

若某个音效文件尚未提供：
- 该事件触发时静默跳过，不报错、不中断游戏。
- 控制台输出一条 Warning，格式：`[AudioManager] 缺少音频文件：<文件名>`。
- 配置表中该条目的其余字段照常保留，文件补齐后无需改代码即可生效。
- 完成后向用户列出「缺失文件清单」。
